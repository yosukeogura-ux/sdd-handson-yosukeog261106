# テスト記録規約

テスト記録は機能ごとに次の2ファイルへ分けて保存する。書式・雛形は `docs/test/README.md` を正とする。

| ファイル | 内容 | 更新方式 |
|---|---|---|
| `docs/test/<機能名>.md` | テストケース一覧（ID・観点・ケース名・期待結果・最新結果） | 行の追記＋「最新結果」列の更新（常に現在の状態を表す） |
| `docs/test/<機能名>-履歴.md` | 実行履歴と失敗の記録 | 末尾への追記のみ |

## 記録タイミング
| タイミング | 記録する内容 |
|---|---|
| 実装前（テストケース設計時） | 一覧ファイルにテストケースを作成・追記し（ID・観点・ケース名・期待結果。最新結果は −）、ユーザーの承認を得る |
| テストコードの作成・変更時 | 一覧ファイルと実装の対応を確認し、ケースの追加・変更が生じた場合は一覧へ反映してユーザーの承認を得る |
| テスト実行後（成否を問わず） | 履歴ファイルに1エントリ追記し、一覧ファイルの「最新結果」列を ○ / × / − に更新 |
| 失敗の発生時 | 履歴ファイルに失敗の記録（事象・原因・修正方法）を自然言語で追記 |
| 失敗修正後の再実行 | 履歴ファイルに新エントリを追記し、該当する失敗の記録の「対応状況」を更新 |

## 追記の原則
- 履歴ファイル（`<機能名>-履歴.md`）は末尾への追記のみ。過去のエントリと失敗の記録の本文は書き換えない（× → ○ の経緯を履歴として残すため）。例外として更新してよいのは失敗の記録の「対応状況」行だけ
- 一覧ファイル（`<機能名>.md`）は常に「現在のテストケースと最新結果」だけを表すよう更新する。経緯・変更履歴は書かない（経緯は履歴ファイルが担う）

## 失敗時の必須対応
1. 一覧ファイルの該当ケースに × を記録し、履歴ファイルに失敗の記録（事象・原因・修正方法）を自然言語で残す
2. **ユーザーに必ず報告する**。記録して終わりにせず、失敗ケース・原因・修正方針を応答の先頭で明示する。報告なしに次の作業へ進まない
3. 修正後に再実行し、履歴ファイルに新しいエントリとして追記する（× のエントリは消さない）

## 対象外
- 一時的な実験・使い捨てのスクリプト実行は記録不要
- カバレッジ数値の推移など、CI が機械的に残せる情報はここに転記しない
- `.claude/` 配下のテンプレート運用ファイル（フック・その検証スクリプト等）はプロダクトのテストではないため対象外（Stop フックの検査も `.claude/` 配下を除外している）。フックの検証は `.claude/hooks/tests/test_hooks.py` の手動実行で行う
