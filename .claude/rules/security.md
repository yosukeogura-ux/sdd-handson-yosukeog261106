# セキュリティ規約

## 秘密情報の扱い
- APIキー・パスワード・トークン・接続文字列をソースコードにハードコードしない
- 秘密情報は環境変数または `.env`（`.gitignore` 登録必須）で管理する
- `.env.example` にはキー名とダミー値のみ記載し、実値は絶対に書かない
- ログ・エラーメッセージ・コミットメッセージに秘密情報や個人情報を出力しない
- 誤って秘密情報をコミットした場合: 履歴の削除だけでは不十分。**即座に該当キーをローテーション（無効化・再発行）**し、ユーザーに報告する

## 禁止パターン
| パターン | リスク | 代替 |
|---|---|---|
| 文字列連結による SQL 組み立て | SQLインジェクション | プレースホルダ / ORM |
| `innerHTML` への未エスケープ代入 | XSS | textContent / フレームワーク標準のバインディング |
| `eval` / `new Function` / `exec` への外部入力 | 任意コード実行 | 設計から排除する |
| ユーザー入力によるファイルパス組み立て | パストラバーサル | 許可リスト + 正規化後の検証 |
| 信頼できないデータの `pickle` 等のデシリアライズ | リモートコード実行 | JSON 等の安全な形式 |
| 平文パスワード保存 / 独自ハッシュ | 漏洩時の被害拡大 | bcrypt / argon2 |
| 独自実装の暗号・`Math.random` でのトークン生成 | 推測可能 | 標準ライブラリの暗号論的乱数 |

## 必須対策
- **入力検証**: フロントエンド・バックエンドの両方で行う。バックエンド側の検証を正とする
- **認可チェック**: 認証（誰か）と認可（何ができるか）を区別し、リソースアクセス時は所有者確認を行う（IDOR 対策）
- **出力エスケープ**: 出力先（HTML / SQL / シェル / URL）に応じたエスケープを行う
- **依存関係**: ライブラリ追加前にメンテ状況・既知脆弱性を確認する（`npm audit` / `pip-audit` 等）。追加はユーザー許可制
- **最小権限**: DBユーザー・APIトークン・IAM は必要最小限の権限にする
- **エラー応答**: 内部情報（スタックトレース・SQL・ファイルパス）を外部に返さない
