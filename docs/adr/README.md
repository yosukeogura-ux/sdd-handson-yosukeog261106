# ADR運用ルール

## ADRとは
Architecture Decision Record。覆すコストが高い技術判断の「経緯と理由」を残す記録。

## 記載対象（architecture スキルの基準と同一）
- 後から覆すコストが高い判断（DB選定、認証方式、API形式など）
- 複数の妥当な選択肢を比較検討した判断
- 規約（.claude/rules/）からの意図的な逸脱

## 採番・命名
- `ADR-001-短い判断内容.md` のように「ADR-」+ 前ゼロ付き3桁連番 + 短い判断内容で命名する（CLAUDE.md 動作規定「振る舞いの制限」の `ADR-連番-短い判断内容.md` 形式）。連番は既存の最大番号+1で採番し、欠番は詰めない
- ファイル名の短い判断内容は、本文1行目のタイトル（`# ADR-001: <決定内容の要約>`）と対応する要約にする（例: `ADR-001-セッションログ自動保存.md`）
- テンプレートは `ADR-000-template.md` をコピーして使う

## 状態管理
- 提案中 → 承認 → 必要に応じて 廃止（ADR-XXX で置換）
- 一度「承認」にした本文は書き換えない。判断が変わったら新しいADRで置き換える

## 反映
- 「承認」になったら結論を `docs/design/` の該当ファイルに反映する（全体構成・レイヤ構成・依存方向は `architecture.md`、ディレクトリ構造・実装規約は `tech.md`）
