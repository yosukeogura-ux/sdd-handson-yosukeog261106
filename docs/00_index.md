# ドキュメント索引

## 全体・要求
| 場所 | 役割 |
|---|---|
| `product/PRD.md` | プロダクト全体の目的・背景・スコープ・成功条件 |
| `requirements/common.md` | 全機能に共通する業務要求・共通仕様 |
| `requirements/non-functional.md` | 性能・セキュリティ・権限・運用などの非機能要件 |
| `drafts/` | 合意前の要求を言語化する叩き台。合意後に PRD・features・changes 等へ反映して削除 |

## 新規開発・改修
| 場所 | 役割 |
|---|---|
| `features/` | 機能単位の現在仕様の正（新規・既存とも）。新規開発で作成し、改修では実装前に変更後仕様を反映する |
| `changes/` | 既存機能の改修・障害対応・仕様変更。改修単位で差分管理し、完了後は当時の記録として残す |

## 設計・運用
| 場所 | 役割 |
|---|---|
| `design/architecture.md` | 全体構成・レイヤ構成・依存方向 |
| `design/tech.md` | ディレクトリ構造・プロジェクト固有の実装規約 |
| `design/common-spec.md` | 機能横断の共通詳細仕様（共通入力チェック・共通メッセージ）。機能別の詳細仕様は `features/` 側 |
| `design/data/` | データモデル定義。1テーブル1ファイル＋全体像 |
| `design/screen.md` | 画面一覧・画面遷移 |
| `design/api.md` | API・外部連携一覧 |
| `design/batch.md` | バッチ・ジョブ一覧 |
| `operations/` | 環境・デプロイ・リリース手順 |

## 記録
| 場所 | 役割 |
|---|---|
| `project/plan.md` | 開発計画・フェーズ構成 |
| `project/progress.md` | 現在地・TODO。セッション開始時に自動注入される |
| `project/log/` | セッション単位の要約ログ。「ログを記録して」の依頼で Claude が追記する |
| `adr/` | 後戻りしづらい技術判断の記録 |
| `test/` | テストケース・実行履歴・失敗記録 |
