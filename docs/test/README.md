# テスト記録の運用

<!-- このファイルは書式の定義。実際の記録は機能ごとに docs/test/<機能名>.md（テストケース一覧）と docs/test/<機能名>-履歴.md（実行履歴・失敗の記録）の2ファイルを作成して行う -->

機能ごとのテストケースと実行結果を記録するディレクトリ。記録の規約（タイミング・追記原則・失敗時の対応）は `.claude/rules/test-documentation.md` を正とする。機能仕様そのものは `docs/features/`、改修差分は `docs/changes/`、共通仕様は `docs/design/` に書き、ここには書かない。

## ファイル規則
- 機能ごとに次の2ファイルをペアで作成する
  - `docs/test/<機能名>.md`: テストケース一覧（例: `docs/test/ユーザー認証.md`）。常に「現在のケースと最新結果」だけを表す
  - `docs/test/<機能名>-履歴.md`: 実行履歴と失敗の記録（例: `docs/test/ユーザー認証-履歴.md`）。末尾への追記のみ
- 機能名は `docs/features/` の機能単位に合わせる。既存機能の改修では対象機能の既存の一覧・履歴ファイルへ追記し、改修名の新ファイルを作らない（対象機能のファイルが未作成なら機能名で作成する）。機能に紐付かない改修のみ `docs/changes/` の改修名を使う
- 単一機能に属さないテスト（E2E・スモークテスト・回帰スイート全体など）は `docs/test/横断-<種別>.md`・`docs/test/横断-<種別>-履歴.md` に記録する（例: `docs/test/横断-E2E.md`）
- ファイルが増えたらサブフォルダで整理してよい（例: `docs/test/認証/ログイン.md`）。一覧と履歴のペアは必ず同じフォルダに置く。直下の `README.md`（本ファイル）だけは書式定義として固定
- テストケース ID は `TC-001` から一覧ファイル内で連番を振る。削除したケースの ID は再利用しない（履歴ファイルに残る過去の ID と衝突させないため）

## 記録規則
- **テストケース一覧**（`<機能名>.md`）: ケースを追加したら行を追記し、ケースの変更・削除も一覧へ直接反映する（常に現在の状態だけを表し、経緯は残さない）。「最新結果」列は実行のたびに最新の ○ / × / − へ更新する
- **実行履歴**（`<機能名>-履歴.md`）: テストを実行するたびに（成功・失敗を問わず）末尾へ1エントリ追記する。過去のエントリは書き換えない
- **失敗の記録**（`<機能名>-履歴.md`）: × が出たら、該当する実行エントリの配下に事象・原因・修正方法を自然言語で残す。修正が完了したら「対応状況」行のみ更新してよい（本文は書き換えない）
- **手動テスト**: 画面の目視確認・受け入れ確認などもテストケースとして記録してよい。観点列に「手動」と付け、ケース名の列には確認手順の要約を書く

## 結果の表記
| 表記 | 意味 |
|---|---|
| ○ | 成功 |
| × | 失敗 |
| − | 未実施・スキップ |

## テストケース一覧ファイルの雛形（`docs/test/<機能名>.md`）

```markdown
# <機能名> テストケース一覧

<!-- 書式: docs/test/README.md / 規約: .claude/rules/test-documentation.md / 実行履歴: docs/test/<機能名>-履歴.md -->

| ID | 観点 | ケース名（テストコード上の名前） | 期待結果 | 最新結果 |
|---|---|---|---|---|
| TC-001 | 正常系 | login_valid_credentials_returns_token | ログインに成功しトークンが返る | ○ |
| TC-002 | 異常系 | login_wrong_password_returns_401 | 401 エラーが返る | × |
```

## 履歴ファイルの雛形（`docs/test/<機能名>-履歴.md`）

```markdown
# <機能名> テスト実行履歴

<!-- 書式: docs/test/README.md / 規約: .claude/rules/test-documentation.md / テストケース一覧: docs/test/<機能名>.md -->
<!-- 末尾への追記のみ。過去エントリと失敗の記録の本文は書き換えない（更新してよいのは「対応状況」行だけ） -->

## 2026-07-03 14:30 — 範囲: ユーザー認証の全テスト
- コマンド: `pytest tests/test_auth.py`
- 結果: 5 passed / 1 failed

| ID | 結果 |
|---|---|
| TC-001 | ○ |
| TC-002 | × |

### 失敗の記録: TC-002
- **事象**: パスワード不一致時に 401 ではなく 500 が返る
- **原因**: 認証サービスが `InvalidPassword` 例外を捕捉しておらず、未処理例外としてサーバエラーになっている
- **修正方法**: `AuthService.login` で `InvalidPassword` を捕捉し、401 応答に変換するハンドリングを追加する
- **対応状況**: 未対応
```
